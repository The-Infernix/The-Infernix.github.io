- Scroll progress bar, sticky header, scroll-triggered reveals, and terminal typewriter — all respecting `prefers-reduced-motion`

- No build step or third-party JavaScript dependencies

## 1. Create the GitHub Pages repository

1. Sign in to GitHub as `The-Infernix`.
2. Create a **public** repository named exactly `The-Infernix.github.io`.
3. Upload the contents of this folder to the repository root (not the enclosing folder).
4. In **Settings → Pages**, select **Deploy from a branch**, branch `main`, folder `/ (root)`, then save.
5. Wait for the deployment to finish. Expected site URL: `https://the-infernix.github.io/`.

> GitHub Pages user sites require the repository name to match the account's username plus `.github.io`. If GitHub shows a different username in your profile URL, rename the repository and update every canonical URL in `index.html`, `robots.txt`, and `sitemap.xml` to match the actual site URL.

## 6. Regenerating the social preview images

Every page ships a **PNG** `og:image`, never an SVG. LinkedIn, Twitter/X, Facebook, WhatsApp, Slack, and Discord do not render SVG in link previews — LinkedIn's own guidance lists JPG, PNG, and GIF only — so an SVG `og:image` yields a blank card. LinkedIn also wants at least 1200×627 px and no more than 5 MB; every card here is exactly 1200×630.

There are two kinds of card:

| Card | Used by | Source |
| --- | --- | --- |
| `assets/social-preview.png` | Homepage and blog index | `assets/social-preview.svg` |
| `assets/og/*.png` | One per article | `tools/make_og_cards.py` |

### Article cards

`tools/make_og_cards.py` defines each article card as inline SVG and rasterizes it with headless Chrome, so the typography uses the same self-hosted woff2 files as the site. Edit the `CARDS` list in that file, then:

```powershell
python tools/make_og_cards.py
```

It writes `assets/og/<slug>.png` for every entry. Requires Google Chrome and Python 3. It is optional tooling — the site serves the committed PNGs directly and has no build step.

After adding an article, point its `og:image`, `twitter:image`, and JSON-LD `image` at the new PNG, keep `og:image:width`/`height`/`type` in sync, and add an `<image:image>` entry to `sitemap.xml`.

### The generic card

`assets/social-preview.svg` is the editable source; `assets/social-preview.png` is what the pages point at. After editing the SVG, re-render it:

```powershell
$svg = Get-Content .\assets\social-preview.svg -Raw
$wrap = "<!doctype html><html><head><meta charset='utf-8'><style>html,body{margin:0;padding:0;background:#090b0f;width:1200px;height:630px;overflow:hidden}svg{display:block}</style></head><body>$svg</body></html>"
Set-Content -Path "$env:TEMP\og-wrap.html" -Value $wrap -Encoding utf8
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 --window-size=1200,630 --screenshot="$PWD\assets\social-preview.png" --user-data-dir="$env:TEMP\og-cdp" "file:///$($env:TEMP -replace '\\','/')/og-wrap.html"
```
